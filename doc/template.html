agent-distro

One command starts an AI coding agent. One file in your repository sets it up.

agent-distro is an open-source command that runs $agents.count$ AI coding agents: $agents.list$. You pick an agent, and Nix fetches it, so you install none of the agents yourself. Nix is a package manager for Linux and macOS.

You put a plugin.json file in your repository. It names the skills and the MCP servers that your team uses. A skill is a file of instructions that an agent reads. An MCP server is a program that gives an agent tools. Every agent that you start in the repository loads them. The file and its skills are a profile. The documentation calls an agent a harness.

$$ nix run github:juspay/agent-distro

The recording scrolls sideways.

  • One file sets up every agent. The plugin.json in your repository names your skills and MCP servers once. Each of the $agents.count$ agents loads them when it starts there.
  • The agents stay current. The project looks for new releases of the agents four times a day. A new release reaches the main branch after the builds and the tests in virtual machines pass.
  • Nothing is copied into your repository. agent-distro reads plugin.json each time an agent starts. You commit no generated directory for each agent.

What it takes today. You need Nix, the package manager that fetches the agents. agent-distro runs on x86_64 Linux, ARM Linux, and Apple Silicon Macs. It does not run on Windows or on an Intel Mac. Each agent needs your own account, or a key that your profile asks for. On ARM Linux the first run compiles, because the project's binary cache holds builds for x86_64 Linux and Apple Silicon only.

A profile is one file in your repository

A profile is a plugin.json file and the skills beside it. agent-distro reads it each time an agent starts, and writes nothing into your repository.

The smallest profile is four lines:

{
  "$$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "my-repo"
}

To start a profile with a sample skill, run this command in your repository:

nix flake init -t github:juspay/agent-distro

The file follows the Agent Plugins format, which holds skills and MCP servers. Under extensions."asia.nixos.agent-distro", a profile can add four more things:

  • plugins: more plugins, by path or by flake reference.
  • packages: programs from nixpkgs, the Nix package collection, put on PATH for the MCP servers.
  • env: environment variables. agent-distro asks for a secret one and never writes it to a file.
  • settings: default settings for Oh My Pi and OpenCode only.

When agent-distro is the wrong choice

agent-distro is the wrong choice today if one of these is true:

  • You do not want to install Nix.
  • You use Windows or an Intel Mac.
  • Your agent is not one of the $agents.count$.
  • Your setup needs hooks, prompts, or subagents.
  • You need a lockfile, or an organization's policy for what agents load.

When agent-distro may suit you

agent-distro may suit you if one of these is true:

  • Your team uses more than one of the $agents.count$ agents and wants the same skills in each.
  • You use Nix already.
  • You want the agents kept current without an installer for each.
  • You do not want a generated directory for each agent in your repository.

Home Manager keeps the agents on your machine current

Home Manager is a Nix tool that manages the programs of your user account. Its agent-distro module puts every agent on your PATH. Your machine then checks for a new build four times a day. It installs only what the binary cache holds, so it never compiles. Read how to install and keep the agents updated.

Also inside Kolu

Kolu can put the agents in every new terminal

Kolu adds no agents until you switch them on. With the switch on, every new terminal has the agents on its PATH, kept up to date. Each agent starts with Kolu's plugin loaded, so it can drive your other Kolu terminals.
